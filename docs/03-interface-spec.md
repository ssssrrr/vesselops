## 1. 개요

본 문서는 시스템 구성요소 간 주고받는 데이터의 **규격**을 정의한다.
프로토콜, 주소 체계, 페이로드 구조, 데이터 타입, 오류 처리 방식을 포함한다.

### 1.1 이 문서가 필요한 이유

실무에서 이 유형의 시스템을 구축하는 작업의 상당 부분은 **타 시스템과 규격을 맞추는 일**이다.
AMS 제조사와 태그 목록을 주고받고, NodeId 형식을 확인하고, 데이터 타입과 단위를 합의하는 과정이
선행되지 않으면 개발을 시작할 수 없다. 본 문서는 그 합의 결과를 기록한 것에 해당한다.

### 1.2 인터페이스 경계

```
[설비]         [본선]              [위성]         [육상 클라우드]        [사용자]
 AMS ──IF-01──> edge-gw ──IF-02──> broker ──> ingest ──IF-03──> DB
(OPC UA)                  (MQTT)                  │            ▲
                                                  │IF-04       │
                                                  ▼            │
                                              브라우저 <──IF-05── api
```

## 3. IF-01 · AMS ↔ Edge 수집기 (OPC UA)

### 3.1 접속 정보

| 항목 | 개발 환경 | 실선 적용 시 |
|---|---|---|
| 엔드포인트 | `opc.tcp://sim-fleet:4840/vesselops` | `opc.tcp://<AMS IP>:4840/<경로>` |
| 보안 정책 | `None` (내부 네트워크 한정) | `Basic256Sha256` |
| 메시지 모드 | `None` | `SignAndEncrypt` |
| 인증 방식 | Anonymous | 사용자명/비밀번호 또는 인증서 |
| **세션 권한** | **읽기 전용** | **읽기 전용 (필수)** |
| 세션 타임아웃 | 60초 | 60초 |

> **FR-107 준수:** 클라이언트는 Write 및 Method 호출 기능을 구현하지 않는다.
> 실선 적용 시 AMS 측에서도 읽기 전용 계정을 발급받아 이중으로 차단한다.

### 3.2 주소공간 구조

```
Objects
 └── Vessels
      ├── IMO9876543                  (Object)
      │    ├── ME                     (Object — 주기관)
      │    │    ├── ME_RPM            (Variable, Double)
      │    │    ├── ME_LOAD           (Variable, Double)
      │    │    ├── ME_EXH_T_CYL01    (Variable, Double)
      │    │    │   ⋮
      │    │    └── ME_VIB_RMS        (Variable, Double)
      │    ├── DG1 / DG2              (Object — 발전기관)
      │    ├── TC1                    (Object — 과급기)
      │    └── SHAFT                  (Object — 축계)
      ├── IMO9876544
      ├── IMO9812345
      └── IMO9754321
```

### 3.3 NodeId 명명 규칙

```
ns=1;s=IMO{IMO번호}.{장비코드}.{태그코드}
```

| 예시 | 의미 |
|---|---|
| `ns=1;s=IMO9876543.ME.ME_RPM` | STELLA PIONEER 주기관 회전수 |
| `ns=1;s=IMO9876543.ME.ME_EXH_T_CYL04` | STELLA PIONEER 주기관 4번 실린더 배기온도 |
| `ns=1;s=IMO9754321.DG2.DG2_POWER` | PACIFIC HARVEST 2번 발전기 출력 |

> **실선에서는 이 규칙이 통하지 않는다.** AMS 제조사마다 NodeId 형식이 달라
> (`ns=2;s=Main.Engine.Cyl04.ExhTemp`, `ns=3;i=1047` 등) 문서만으로 알 수 없는 경우가 많다.
> 착수 시 **UaExpert 등 클라이언트 도구로 주소공간을 탐색하여 실제 NodeId 를 확보**하고,
> 본 문서의 태그맵을 해당 형식으로 갱신하는 절차를 거친다.

### 3.5 구독 파라미터

| 항목 | 값 | 근거 |
|---|---|---|
| Publishing Interval | 1000 ms | 계측 주기와 일치 |
| Sampling Interval | 1000 ms | 서버 측 샘플링 |
| Queue Size | 10 | 일시적 지연 시 값 손실 방지 |
| Discard Oldest | true | 큐가 차면 오래된 값부터 폐기 |

> 설정으로 전환하며, 폴링 주기는 1초로 동일하다.

### 3.6 품질코드 매핑

OPC UA StatusCode 를 OPC 관례 품질코드로 변환해 저장한다.

| OPC UA StatusCode | 분류 | 저장값 (`telemetry.quality`) | 처리 |
|---|---|---|---|
| `Good` (0x00000000) | 양호 | **192** | 정상 적재 |
| `Uncertain` (0x40xxxxxx) | 불확실 | **64** | 적재하되 화면에 표시 |
| `Bad` (0x80xxxxxx) | 불량 | **0** | 적재하되 알람 판정에서 제외 |

> 품질이 나쁜 값을 **버리지 않고 저장**하는 이유: 센서 고장 자체가 진단 대상이기 때문이다.
> 다만 알람 룰 엔진은 `quality = 192` 인 값만 평가하여 오경보를 방지한다.

### 3.7 Deadband 필터 (FR-103)

```
전송 조건:  |현재값 − 마지막 전송값| ≥ Deadband
            또는  (현재시각 − 마지막 전송시각) ≥ Heartbeat(60초)
```

Heartbeat 를 두는 이유는 값이 변하지 않을 때도 **"살아 있고 값이 그대로"** 임을
주기적으로 알려야 화면에서 통신 단절과 구분되기 때문이다.

#### 대역폭 효과

| 구분 | 전송률 | 월 데이터량/척 | 판정 |
|---|---|---|---|
| 필터 없음 (142값/초 × 약 65 byte) | 약 74 kbps | 24 GB | ❌ |
| Deadband 만 적용 | 약 15 kbps | 약 5 GB | ❌ NFR-07(1.5GB) 초과 |
| **Deadband + 적응형 전송 + 압축** | **약 4.6 kbps** | **약 1.5 GB** | ✅ 충족 |

> 실측치는 `08-test.md` 에 기록한다.

### 3.8 전송 모드 전환 (FR-108 ~ FR-110)

Edge 수집기는 두 가지 전송 모드로 동작하며, **판정은 Edge 가 자체 수행한다.**
육상은 요약 데이터만 수신하므로 조기 감지가 구조적으로 불가능하고, 왕복 지연도 더해진다.

#### 3.8.1 모드 정의

| 모드 | 전송 내용 | 주기 | 대역 | 우선순위 |
|---|---|---|---|---|
| `summary` (기본) | 1분 통계 (avg/min/max/sd/n) | 60초 | 약 0.3 kbps | P2 |
| `raw` (고해상도) | 1초 원본 | 1초 | 약 15 kbps | P1 |

#### 3.8.2 Pre-trigger 링버퍼

| 항목 | 값 | 설명 |
|---|---|---|
| 보관 대상 | 1초 원본 전량 | **전송 모드와 무관하게 항상 적재** |
| 보관 기간 | 600초 (10분, 설정 가능) | 대역 부담 시 180초로 축소 |
| 자료구조 | 고정 크기 링버퍼 (메모리) | 142태그 × 600초 ≈ 85,200건 ≈ 약 5 MB |
| 소급 전송 | 트리거 시 버퍼 전량을 P1 큐로 발행 | `mode:"raw"`, `buffered:true` |
| 전송량 | 1회 약 5 MB | 트리거 시에만 발생 |

> **이 설계의 요점은 전환 속도가 아니다.** 트리거 판정이 다소 늦어도
> 그 사이 구간은 이미 링버퍼에 들어 있다. 오실로스코프 pre-trigger 와 같은 원리이며,
> 고장 진단에서 가장 중요한 **이상 확정 이전 구간**을 보존하는 것이 목적이다.

#### 3.8.3 전환 트리거 조건

| 조건 | 기준 | 예시 |
|---|---|---|
| 임계값 근접 | 경보 설정값의 **80%** 도달 | 추력베어링 HI 75℃ → 60℃ 도달 시 전환 |
| 편차 확대 | 알람 편차 기준의 **60%** 도달 | 편차 알람 50℃ → 30℃ 도달 시 전환 |
| 변화율 초과 | 육상 변화율 기준의 **80%** 도달 | 육상 60초간 5℃ → 4℃ 도달 시 전환 |
| 품질 저하 | Bad/Uncertain 품질 **5회 연속** | 센서 이상 |
| **복귀** | 모든 조건 해소 후 **정상 600초 지속** | 채터링 방지 |

태그별 적용 기준값은 `06-function-spec.md` 4.5 에 정리한다. 주기관 정지 중에는 품질 저하만 판정한다.

> 전환 기준을 **육상 알람 기준보다 낮게** 두어 오탐을 허용한다.
> 불필요한 고해상도 전환의 비용(일시적 대역 증가)이, 늦게 전환해 진단 데이터를 잃는 비용보다 작다.

#### 3.8.4 성능 지표

## 4. IF-02 · Edge 수집기 ↔ 브로커 (MQTT)

### 4.1 접속 정보

| 항목 | 개발 | 실선 적용 시 |
|---|---|---|
| 브로커 | `mqtts://broker:8883` | `mqtts://<육상 브로커>:8883` |
| 프로토콜 버전 | MQTT 3.1.1 | MQTT 3.1.1 |
| 전송 암호화 | TLS 1.2 이상 (실측 TLS 1.3). 평문 리스너 없음 | 동일 |
| 인증 | **클라이언트 인증서** (CN = IMO 번호). 서버 인증서도 같은 CA 로 검증 | 동일. 인증서는 선박 등록 시 발급 |
| 권한 | 자기 IMO 번호의 토픽에만 발행. 구독 불가 | 동일 |
| Client ID | `edge-{IMO번호}` | 동일 |
| Clean Session | `false` | **`false` (세션 보존 필수)** |
| Keep Alive | 60초 | 60초 |

> `Clean Session = false` 로 두어야 재접속 시 브로커가 미전달 메시지를 유지한다.
> 위성통신 단절이 잦은 환경에서 필수 설정이다.

**인증서와 접근 제어** (설계 근거는 `02-architecture.md` ADR-011)

| 인증서 (CN) | 쓰는 쪽 | 브로커가 허용하는 것 |
|---|---|---|
| `broker` | 브로커 (서버 인증서) | — |
| `{IMO번호}` | 해당 선박의 Edge 수집기 | `vesselops/telemetry/{IMO번호}/#`, `vesselops/status/{IMO번호}` **발행만** |
| `ingest-1` | 육상 수집기 | `vesselops/telemetry/#`, `vesselops/status/#` **구독만** |
| `healthcheck` | 브로커 상태 점검 | `$SYS/broker/version` 구독만 |

- 우리 CA 가 발급하지 않은 인증서, 또는 인증서 없는 접속은 TLS 단계에서 끊는다.
- A 선박의 인증서로 B 선박의 토픽에 발행하면 브로커가 버린다. 수집기까지 오지 않는다.
- 설정 원본은 `deploy/mosquitto/mosquitto.conf`, `deploy/mosquitto/acl.conf`.

### 4.2 토픽 체계

| 토픽 | 용도 | QoS | Retain | 우선순위 |
|---|---|---|---|---|
| `vesselops/alarm/{imo}` | **알람 이벤트 (차기)** | 1 | false | **P0** |
| `vesselops/telemetry/{imo}/{equipment}` | 계측값 전송 (요약·원본 공용) | 1 | false | P1 / P2 |
| `vesselops/status/{imo}` | 선박 접속 상태 · 전송 모드 전환 | 1 | **true** | P0 |

알람을 계측값과 **별도 토픽**으로 분리한 이유는 두 가지다.
첫째, 전송 모드와 무관하게 항상 즉시 전송해야 한다(NFR-10).
둘째, 페이로드가 수백 바이트로 작아 요약 모드에서도 대역 부담이 없다.

- `{imo}` — IMO 번호 7자리 (예: `9876543`)
- `{equipment}` — 장비코드 (`ME`, `DG1`, `DG2`, `TC1`, `SHAFT`)

**예시**
```
vesselops/telemetry/9876543/ME
vesselops/telemetry/9754321/DG2
vesselops/status/9876543
```

### 4.3 계측값 페이로드

전송 모드에 따라 `values[]` 의 구조가 달라진다. 구분은 `mode` 필드로 한다.

#### 4.3.1 공통 헤더

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `imo` | string(7) | ✅ | IMO 번호 |
| `eq` | string | ✅ | 장비코드 |
| `seq` | integer | ✅ | 발행 순번. 선박별 단조 증가. 누락 구간 탐지용 |
| `sentAt` | ISO8601 UTC | ✅ | 발행 시각 |
| `buffered` | boolean | ✅ | **true 면 단절 버퍼 또는 Pre-trigger 링버퍼에서 소급 전송된 것** |
| `mode` | `"raw"` \| `"summary"` | ✅ | 전송 모드 |
| `period` | integer | 요약 시 | 집계 구간(초). `summary` 일 때만 |
| `values` | array | ✅ | 계측값 배열. 1회 최대 200건 |

#### 4.3.2 원본 전송 (`mode: "raw"`)

```json
{
  "imo": "9876543",
  "eq": "ME",
  "seq": 104321,
  "sentAt": "2026-09-29T02:14:33.120Z",
  "buffered": false,
  "mode": "raw",
  "values": [
    { "t": "ME_RPM",         "ts": "2026-09-29T02:14:33.000Z", "v": 83.4,  "q": 192 },
    { "t": "ME_LOAD",        "ts": "2026-09-29T02:14:33.000Z", "v": 82.1,  "q": 192 },
    { "t": "ME_EXH_T_CYL04", "ts": "2026-09-29T02:14:33.000Z", "v": 447.2, "q": 192 }
  ]
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `values[].t` | string | 태그코드 |
| `values[].ts` | ISO8601 UTC | **계측 시각** (발행 시각이 아님) |
| `values[].v` | number \| null | 계측값 |
| `values[].q` | integer | 품질코드 (192/64/0) |

#### 4.3.3 요약 전송 (`mode: "summary"`)

```json
{
  "imo": "9876543",
  "eq": "ME",
  "seq": 104322,
  "sentAt": "2026-09-29T02:15:00.200Z",
  "buffered": false,
  "mode": "summary",
  "period": 60,
  "values": [
    { "t": "ME_EXH_T_CYL04", "ts": "2026-09-29T02:14:00.000Z",
      "avg": 385.2, "min": 381.0, "max": 448.7, "sd": 12.4, "n": 60, "q": 192 }
  ]
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `values[].ts` | ISO8601 UTC | **집계 구간 시작 시각** |
| `values[].avg` | number | 구간 평균 |
| `values[].min` / `max` | number | 구간 최소·최대 |
| `values[].sd` | number | 표준편차 |
| `values[].n` | integer | 표본 수 (결측 판단용) |
| `values[].q` | integer | 구간 내 **최악 품질코드** |

> **평균만 보내지 않는 이유.** 요약이 평균뿐이면 순간 스파이크가 사라져 육상에서 이상을 볼 수 없다.
> 위 예시에서 `avg` 는 385℃ 로 정상이지만 `max` 가 448℃ 이므로 육상에서도 즉시 이상을 인지한다.
> 값당 약 20 byte 가 늘지만 1분에 1회이므로 대역 영향은 무시할 수준이다.

#### 4.3.4 필드명 축약 및 시각 표기 원칙

> **필드명을 `t`,`v`,`q`,`ts` 로 줄인 이유:** 위성통신 구간이라 바이트 단위가 비용이다.
> `tagCode`/`value`/`quality` 로 쓰면 값 하나당 약 25 byte 가 추가되어,
> 142 태그 기준 초당 3.5 KB, 월 9 GB 가량 늘어난다.

> **시각은 반드시 UTC 로 기록한다.** 선박은 항해 중 현지시각을 변경하므로
> 본선 로컬시각을 쓰면 시계열이 역전되거나 중복된다.

### 4.4 알람 페이로드 (`vesselops/alarm/{imo}`) — 차기

> **현재 버전의 알람 판정은 육상 업무 API 가 수행한다** (`06-function-spec.md` 6.3).
> 본선 Edge 는 전송 모드 전환을 위한 이상 징후만 판정하고, 이 토픽은 아직 발행하지 않는다.
> 통신 단절 중에도 본선에서 알람을 확정해 복구 즉시 전달하려면 본선 판정이 필요하므로 규격은 유지한다.

```json
{
  "imo": "9876543",
  "eq": "ME",
  "tag": "ME_EXH_T_CYL04",
  "ruleType": "DEVIATION",
  "severity": "HI",
  "value": 447.2,
  "reference": 385.2,
  "deviation": 62.0,
  "message": "4번 실린더 배기온도가 평균 대비 62℃ 편차 (연료분사밸브/배기밸브 점검 필요)",
  "raisedAt": "2026-09-29T02:15:03.000Z"
}
```

전송 모드와 무관하게 **P0 우선순위로 즉시 단독 발행**한다.

### 4.5 상태 토픽 및 유언 메시지(LWT)

접속 시 발행:
```json
{ "imo": "9876543", "online": true, "at": "2026-09-29T02:00:00.000Z", "mode": "raw" }
```

전송 모드가 바뀔 때 발행 (FR-108):
```json
{ "imo": "9876543", "online": true, "at": "2026-10-10T08:17:02.113Z",
  "mode": "raw", "reason": "DEVIATION", "triggerTag": "ME_EXH_T_CYL04" }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `online` | boolean | 접속 여부 |
| `at` | ISO8601 UTC | 접속 시각 또는 **Edge 가 모드 전환을 판정한 시각** |
| `mode` | `"raw"` \| `"summary"` | 현재 전송 모드 |
| `reason` | string | 전환 사유. `DEVIATION` / `THRESHOLD_NEAR` / `RATE` / `QUALITY` / `RECOVERED`. 전환 시에만 포함 |
| `triggerTag` | string | 전환을 유발한 태그코드. 복귀(`RECOVERED`) 시에는 없음 |

육상 수집기는 `reason` 이 있는 메시지를 `edge_mode_event` 에 기록한다.

**LWT (Last Will and Testament)** — 비정상 종료 시 브로커가 대신 발행:
```json
{ "imo": "9876543", "online": false, "at": null, "reason": "unexpected_disconnect" }
```

> LWT 를 쓰면 Edge 가 응답 없이 끊겨도 **브로커가 대신 알려준다.**
> 애플리케이션이 타임아웃으로 추정하는 것보다 빠르고 정확하다.
> `Retain = true` 이므로 나중에 접속한 구독자도 마지막 상태를 즉시 받는다.

### 4.6 배치·버퍼링 및 송신 우선순위

**송신 우선순위 큐 (FR-110)**

| 등급 | 내용 | 처리 |
|---|---|---|
| **P0** | 알람 이벤트 | 즉시 단독 발행. 다른 큐를 앞지른다 |
| **P1** | 고해상도 원본 · Pre-trigger 소급분 · 단절 버퍼분 | P2 보다 우선 |
| **P2** | 정기 요약 | 잔여 대역으로 전송 |

정기 요약이 큐에 적체되어 있어도 알람과 고해상도 데이터가 먼저 나간다.

**배치·버퍼링 규칙**

| 상황 | 동작 |
|---|---|
| 정상 (`summary`) | 1분 집계 산출 후 P2 큐로 발행 |
| 고해상도 (`raw`) | Deadband 통과분을 1초 단위로 묶어 P1 큐로 발행 (최대 200건/메시지) |
| 트리거 발생 | Pre-trigger 링버퍼 전량을 P1 큐로 소급 발행 (`buffered:true`) |
| 브로커 단절 | 로컬 큐에 적재. 상한 **100,000건** 도달 시 낮은 우선순위의 오래된 것부터 폐기. 현재 버전은 메모리 큐이며 디스크 저장은 차기 |
| 재연결 | 버퍼분을 `buffered: true` 로 **시간 순서대로 우선 전송**, 이후 실시간 전환 |
| 재전송 중복 | 수신 측 DB 유니크 제약으로 무시 (FR-156) |

## 5. IF-03 · 육상 수집기 ↔ DB

### 5.1 적재 방식

```sql
INSERT INTO telemetry (ts, tag_id, value, quality)
VALUES ($1, $2, $3, $4), ...          -- 최대 200행 묶음
ON CONFLICT (tag_id, ts) DO NOTHING;  -- 재전송 중복 무시
```

| 항목 | 값 | 근거 |
|---|---|---|
| Flush 조건 | 200건 누적 **또는** 1초 경과 | 처리량과 지연의 절충 |
| 태그 해석 | `(imo, equipment, tagCode)` → `tag_id` **메모리 캐시** | 값마다 조회하면 초당 142회 질의 발생 |
| 미등록 태그 | 자동 등록하지 않고 경고 로그 (FR-154) | 오타·설정 오류가 조용히 유입되는 것을 방지 |

### 5.2 검증 실패 처리 (FR-152)

스키마 검증에 실패한 페이로드는 버리지 않고 격리 테이블에 적재한다.

```sql
INSERT INTO telemetry_rejected (topic, payload, reason) VALUES ($1, $2, $3);
```

| 거부 사유 코드 | 조건 |
|---|---|
| `SCHEMA_INVALID` | 필수 필드 누락 또는 타입 불일치 |
| `UNKNOWN_TAG` | 마스터에 없는 태그코드 |
| `TS_OUT_OF_RANGE` | 계측 시각이 현재 기준 ±24시간을 벗어남 |
| `VALUE_NOT_FINITE` | `NaN`, `Infinity` |

### 6.2 구독 요청 (클라이언트 → 서버)

```json

{
```

```json
{ "type": "vesselStatus", "imo": "9876543", "online": false, "mode": "raw", "at": "2026-10-10T08:09:43.952Z" }
```

### 6.4 수신 현황 푸시 (서버 → 클라이언트)

화면의 "MQTT 수신 현황" 영역에 쓴다. 구독 여부와 무관하게 접속한 전원에게 보낸다.

수집기가 MQTT 메시지를 한 건 받을 때마다 보낸다. 본문(`preview`)은 값 3건까지만 싣는다.

```json
{
  "type": "mqtt",
  "topic": "vesselops/telemetry/9876543/ME",
  "bytes": 833,
  "recvAt": "2026-10-12T07:56:06.502Z",
  "imo": "9876543",
  "mode": "raw",
  "buffered": false,
  "seq": 404,
  "sentAt": "2026-10-12T07:56:06.500Z",
  "count": 10,
  "accepted": 10,
  "rejected": 0,
  "preview": { "imo": "9876543", "eq": "ME", "mode": "raw", "values": [ { "t": "ME_RPM", "ts": "2026-10-12T07:56:06.000Z", "v": 82.793, "q": 192 } ], "seq": 404, "sentAt": "2026-10-12T07:56:06.500Z" }
}
```

| 필드 | 뜻 |
|---|---|
| `bytes` | 받은 MQTT 본문의 크기 |
| `recvAt` − `sentAt` | 본선 발행부터 육상 수신까지의 지연 |
| `count` / `accepted` / `rejected` | 메시지에 든 값의 수 / 적재 대상 / 검증에서 거부된 수 |

1초마다 누적 통계와 브로커 접속 방식을 보낸다.

```json
{
  "type": "ingestStats",
  "at": "2026-10-12T07:56:05.244Z",
  "messages": 1576, "received": 5445, "inserted": 5383, "duplicated": 0, "rejected": 1, "held": 0, "discarded": 0,
  "transport": { "connected": true, "url": "mqtts://broker:8883", "tls": "TLSv1.3", "cipher": "TLS_AES_256_GCM_SHA384", "identity": "ingest-1" }
}
```

`messages` 는 MQTT 메시지 수, 나머지는 계측값 건수다. `transport` 는 수집기가 실제로 맺은 접속에서 읽은 값이다.

> 브라우저로 보내는 구간은 위성통신이 아니므로 필드명을 축약하지 않고
> **가독성을 우선**한다. 구간마다 최적화 기준이 다르다.

| GET | `/performance/compare` | 동형선 비교 | 게스트 | 차기 |
| POST | `/vessels` | 선박 등록 | ADMIN | 차기 |

요청 파라미터와 응답 구조는 `06-function-spec.md` 6.4 에 기술한다.

### 7.3 오류 응답 형식

```json
{
  "timestamp": "2026-09-29T02:14:33Z",
  "status": 403,
  "code": "VESSEL_ACCESS_DENIED",
```

| HTTP | 사용 상황 |

## 8. IF-06 · 시연 제어 API

채용 담당자 및 평가자가 **직접 조작하여 시스템 동작을 확인**할 수 있도록 제공하는 인터페이스.
실선 배포 시에는 비활성화한다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| 메서드 | 경로 | 처리 주체 | 설명 |
|---|---|---|---|
| GET | `/sim/state` | 시뮬레이터 | 주입된 고장 목록, 선박별 운항 프로파일·부하 |
| POST | `/sim/fault` | 시뮬레이터 | 고장 주입 |
| DELETE | `/sim/fault` | 시뮬레이터 | 전체 정상 복귀. `?imo=` 를 주면 해당 선박만 |
| GET | `/sim/link` | Edge 수집기 | 선박별 링크·전송 모드·버퍼 건수·Pre-trigger 보관 초 |
| POST | `/sim/link` | Edge 수집기 | 위성통신 단절/복구 |

### 8.1 고장 주입

```json
POST /sim/fault
{ "imo": "9876543", "type": "CYL_EXH_DEVIATION", "cylinder": 4, "severity": 75 }
```

| `type` | 파라미터 | 효과 | 유발 알람 |
|---|---|---|---|
| `CYL_EXH_DEVIATION` | `cylinder`, `severity`(℃, 기본 75) | 지정 실린더 배기온도를 120초에 걸쳐 상승 | 편차 알람 (FR-302) |
| `LO_PRESSURE_DROP` | — | 윤활유 압력 3.9 → 1.8 bar, 90초에 걸쳐 하강 | 변화율 WARN, 임계값 LO |
| `TC_FOULING` | `severity`(0~1, 기본 0.8) | 소기압 −15%, 배기온도 +25℃, 연료 +5% | 성능 저하 (알람 없음) |
| `THRUST_BRG_HEATING` | — | 추력베어링 온도 분당 +8℃ 상승 (최대 +50℃) | 변화율 알람 (FR-303), 임계값 HI/HIHI |

| 오류 | HTTP | 상황 |
|---|---|---|
| `VESSEL_NOT_FOUND` | 404 | 없는 IMO 번호 |
| `FAULT_TYPE_INVALID` / `CYLINDER_INVALID` | 400 | 지원하지 않는 종류, 범위를 벗어난 실린더 번호 |
| `ENGINE_STOPPED` | 409 | 정박 중이라 주기관이 정지한 선박 |

> 편차 고장의 기본 크기가 75℃ 인 이유: 한 실린더가 오르면 **평균도 함께 오른다.**
> 알람 기준 50℃ 를 확실히 넘기려면 기준보다 크게 올려야 한다 (`06-function-spec.md` 3.4).

### 8.2 통신 단절 재현

```json
POST /sim/link
{ "imo": "9876543", "connected": false }
```

Edge 수집기의 MQTT 발행을 중단시킨다. OPC UA 수집은 계속되며 값은 로컬 버퍼에 쌓인다.
`connected: true` 로 복구하면 버퍼분이 재전송되어 **차트의 빈 구간이 소급 채워진다.**

### 8.3 자동 복귀

| 규칙 | 값 |
|---|---|
| 유휴 자동 복귀 | 마지막 조작 후 **10분** 경과 시 전체 정상 복귀 |
| 자동 이상 발생 | 평상시 무작위로 경미한 이상을 발생시켜 알람 이력을 유지 |

## 9. 공통 오류 처리 및 재시도 정책

| 구간 | 장애 | 처리 | 복구 |
|---|---|---|---|
| IF-01 | OPC UA 세션 끊김 | 지수 백오프 재접속 (1→2→4→8→최대 30초) | 재접속 후 구독 재생성 |
| IF-01 | 특정 노드 읽기 실패 | 해당 태그만 `quality=0` 으로 기록, 나머지 계속 | 다음 주기에 재시도 |
| IF-02 | 브로커 단절 | 로컬 큐 적재, 재접속 시도 | 재연결 시 버퍼 우선 전송 |
| IF-02 | 큐 상한 도달 | 오래된 것부터 폐기, 경고 로그 | — |
| IF-03 | DB 연결 실패 | 최대 3회 재시도 후 메모리 보류 (상한 10,000건) | 연결 복구 시 적재 |
| IF-03 | 유니크 충돌 | `DO NOTHING` — 정상 동작 | — |
| IF-04 | WebSocket 끊김 | 클라이언트가 3초 후 재연결 | 재연결 시 최신값 재조회 |
| IF-05 | JWT 만료 | 401 응답 | 클라이언트가 로그인 화면 전환 |

### 9.1 로깅 기준

| 수준 | 대상 |
|---|---|
| ERROR | 연결 실패, 적재 실패, 처리 불가 예외 |
