## 4. 범위 조정

### 4.1 판단

주어진 기간으로 전 범위를 얕게 구현하는 것과, 범위를 줄여 **한 줄기를 끝까지 잇는 것** 중 후자를 택했다.

| 기준 | 내용 |
|---|---|
| 지킨 것 | **수집에서 진단까지의 종단 경로.** 시뮬레이터 → OPC UA → Edge → MQTT → 수집기 → DB → 알람 엔진 → 화면이 실제로 동작해야 이 시스템의 가치(편차 진단, 적응형 전송)를 보일 수 있다 |
| 줄인 것 | 종단 경로에 걸리지 않는 기능 — 인증·권한, 마스터 등록 화면, SFOC 등 성능 분석, CI |
| 줄이지 않은 것 | 문서와 시험. 범위를 줄였다는 사실 자체를 추적표에 남겼다 |

### 4.2 문서 선행이 구현 속도를 결정한 방식

9/29 에 구현 대신 인터페이스 정의서와 DB 설계서를 먼저 쓴 것이 결과적으로 구현 속도를 결정했다.
토픽·페이로드·태그맵·테이블·제약조건이 확정돼 있었으므로 구현은 **규격을 코드로 옮기는 일**이 됐다.
구현 중 바뀐 것은 아래 5건이며 전부 문서에 남겼다. 시험에서 찾은 결함 전체는 `08-test.md` 9장.

| 바뀐 것 | 발견 계기 | 반영 |
|---|---|---|
| 편차 고장 기본 크기 60℃ → 75℃ | 한 실린더가 오르면 평균도 올라 편차가 기준에 못 미침 | `03` v1.2, `06` 3.4 |
| 변화율 룰에 방향 추가 | 고장 해소로 값이 복귀할 때 "급변" 오경보 | `04` v1.1 |
| 추력베어링 온도에 열 관성 추가 | 정상 부하 변경이 변화율 알람을 유발 | `06` 3.3 |
| 주기관 정지 시 알람 억제 | 정박 중인 선박이 항상 윤활유 압력 알람 상태 | `06` 6.3.2 |
| 표본 시각을 초 경계에 정렬 | Pre-trigger 구간에서 1초 결측 발견 | `08` TC-303 |

## 6. 잔여 작업

| 우선순위 | 작업 | 근거 |
|---|---|---|
| 1 | CD 활성화 | 서버는 준비됐다. 배포 설정(`09` 7.3)을 넣고 push 로 자동 배포를 확인한다 |
| 2 | 인증·권한 (FR-501~503) | 필수 등급 중 유일하게 착수하지 못한 영역 |
| 3 | SFOC 추세 (FR-401) | 필요한 데이터는 이미 적재 중 |
| 4 | HTTPS (NFR-05) | 도메인 확보 후. MQTT 구간의 TLS 는 적용했다 |
| 4-1 | 인증서 폐기 목록(CRL)·갱신 절차 자동화 | 지금은 발급만 자동이다 (`09` 5.6) |
| 4-2 | 본선·육상을 다른 장비에 두고 시험 | TLS 는 한 서버 안의 컨테이너 사이에서만 확인했다 |
| 5 | 추세의 원본·요약 병합, 디스크 큐 | 실선 프로파일의 완성도 |
| 6 | Node.js 구간 단위 시험 | CI 가 Node.js 3개 프로그램은 문법 검사까지만 한다. 검증(`validate.js`)·Deadband 부터 시험을 붙인다 |
