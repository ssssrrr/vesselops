## 1. 시험 방침

| 구분 | 대상 | 방법 |
|---|---|---|
| 단위 시험 | 핵심 진단 계산 (`CylinderDeviation`) | JUnit 5. 이미지 빌드 단계에서 자동 실행되며 실패하면 이미지가 만들어지지 않는다 |
| 통합 시험 | 컨테이너 7개를 모두 띄운 상태의 종단 동작 | 시연 제어 API 로 고장·단절을 주입하고 DB·로그·API 응답으로 확인 |
| 자동 시험 (CI) | push·PR 마다 | 단위 시험 + Node.js 문법 검사 + 컨테이너 7개 기동 확인 (`.github/workflows/ci.yml`). 통합 시험 TC-101 이하의 고장 주입 시나리오는 자동화하지 않았다 |

> 이 시스템의 결함은 대부분 **프로그램 사이**에서 생긴다 (규격 불일치, 시각 처리, 재전송 중복).
> 그래서 모의 객체로 격리한 시험보다, 실제 브로커·DB 를 띄운 통합 시험에 무게를 뒀다.

판정은 눈으로 본 화면이 아니라 **DB 에 남은 기록**으로 한다. 수치는 전부 아래 환경에서 실측한 값이다.

### TC-104 불량 데이터 격리 (FR-152, 154)

브로커에 직접 발행해 수집기를 시험했다.

| 발행 내용 | 기대 | `telemetry_rejected` 기록 |
|---|---|---|
| 필수 필드가 없는 JSON | 격리 | `SCHEMA_INVALID` |
| JSON 이 아닌 문자열 | 격리 | `SCHEMA_INVALID` |
| 한 메시지에 미등록 태그 1 + 과거 시각 1 + 정상 1 | 불량 2건만 격리, 정상 1건은 적재 | `UNKNOWN_TAG`, `TS_OUT_OF_RANGE` / 적재 +1 |

**✅ 통과** — 값 하나가 불량이어도 같은 메시지의 정상 값은 버리지 않는다.

## 9. 시험 중 발견한 결함

| # | 현상 | 원인 | 조치 | 재시험 |
|---|---|---|---|---|
| 1 | 편차 고장을 60℃ 로 주입해도 알람이 나지 않을 수 있음 | 한 실린더가 오르면 **평균도 함께 올라**, 60℃ 를 올려도 편차는 약 51℃ 에 그친다. 잡음 ±3℃ 를 감안하면 50℃ 기준을 못 넘는 경우가 생긴다 | 기본 크기를 75℃ 로 변경. 원리를 문서에 기재 | TC-202 ✅ |
| 2 | 시뮬레이터 재기동 직후 `추력베어링 온도 급상승` 오경보 | 부하가 바뀌면 베어링 온도가 즉시 따라 움직이도록 모델링돼, 정상 부하 변경이 분당 10℃ 변화로 보임 | 온도에 열 관성(시정수 300초) 적용 | 이후 발생 없음 |
| 3 | 고장을 해제하면 `급변` 알람이 다시 발생할 수 있음 | 변화율을 절댓값으로 비교해 **정상 복귀도 급변**으로 판정 | `rate_limit` 의 부호를 감시 방향으로 정의 (`04` v1.1) | TC-203 ✅ |
| 4 | 실선 프로파일에서 전속 항해 중인 선박이 고장 없이 원본 모드로 전환됨 | 시뮬레이터의 추력베어링 온도가 전부하에서 60℃ 로, Edge 의 임계값 근접 기준(60℃)과 같았음 | 물리모델을 전부하 56℃ 로 조정 | TC-302 에서 다른 선박은 요약 유지 ✅ |
| 5 | **Pre-trigger 구간에서 1초 결측** (120초 중 119초). 수집기의 중복 계수도 평상시에 조금씩 증가 | `setInterval` 이 조금씩 밀리면서, 표본 시각을 초 단위로 내릴 때 **같은 초를 두 번 찍거나 한 초를 건너뜀** | 표본 틱을 매번 다음 초의 0.5초 지점에 맞춰 다시 예약 | TC-303 ✅ 180/180 |

| 6 | 수집기의 `duplicated` 계수가 평상시에도 초당 1건꼴(약 2%)로 증가 | 브로커를 직접 관찰하니 **같은 초에 표본 틱이 두 번** 돌고 있었다 (57ms 간격). 타이머가 이벤트 루프의 캐시된 시각 기준으로 돌아 수십 ms 일찍 깨면, "다음 0.5초 지점"이 아직 지나지 않은 것으로 계산돼 한 번 더 예약된다 | 마지막으로 찍은 초를 기억해 한 초에 한 번만 표본을 뜬다 | 25초 관찰, 1,420건 중 중복 0건 ✅ |
| 7 | 시뮬레이터 재기동 순간 배기온도가 0℃ 로 적재되고(추세에 골), `추력베어링 온도 급상승 (60초간 59.6℃)` 오경보 발생 | OPC UA 변수를 0 으로 만든 뒤 첫 틱에서 값을 채웠다. 그 사이에 접속한 Edge 가 **0 을 품질 Good 으로** 읽어 갔다 | 서버 기동 전에 초기 표본으로 변수를 채운다. 추세 조회는 품질 Good 만 집계한다 | 재기동 후 0값 적재 0건 ✅ |

> 결함 5 는 평상시 화면에서는 보이지 않는다. NFR-09 를 "결측 0건"이라는 **셀 수 있는 기준**으로 적어 두었기 때문에
> 119 라는 숫자가 실패로 판정됐다. 측정할 수 있게 쓴 요구사항이 결함을 찾았다.
>
> 결함 6 은 ADR-005(중복 제거를 DB 제약으로 처리)가 가려 주고 있었다. DB 에는 중복이 한 건도 들어가지 않았고,
> 수집기가 **걸러낸 건수를 세어 두었기 때문에** 원인이 있다는 것을 알 수 있었다. 방어 장치에는 계수를 붙여야 한다.

### 9.1 알려진 한계

| 현상 | 설명 |
|---|---|
| 시뮬레이터를 재기동하면 `추력베어링 온도 급상승` 알람이 한 번 날 수 있다 | 재기동 시 운항 프로파일을 새로 뽑아 부하가 불연속으로 바뀐다. 시뮬레이터가 상태를 저장하지 않기 때문이며, 실선 데이터에서는 생기지 않는 상황이다 |
