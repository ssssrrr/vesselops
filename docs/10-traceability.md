## 1. 이 문서의 용도

요구사항 하나하나가 **어느 설계 문서에 반영되고, 어느 코드로 구현되고, 어느 시험으로 확인됐는지**를 한 줄로 잇는다.
줄이 끊긴 곳이 곧 남은 일이다.

| 상태 | 의미 |
|---|---|
| ✅ 완료 | 구현했고 시험으로 확인했다 |
| 🔶 부분 | 일부만 구현했다. 빠진 부분을 비고에 적는다 |
| ⏳ 차기 | 이번 버전에 구현하지 않았다 |

> 구현하지 않은 항목을 숨기지 않는다. 범위를 줄인 결정과 그 근거를 5장에 남긴다.

## 5. 미구현 항목과 처리 방침

| 항목 | 미구현 사유 | 방침 |
|---|---|---|
| 인증·권한 (FR-501~503) | 시연 사이트는 로그인 없이 보여야 하므로 우선순위를 뒤로 뒀다 | 차기 1순위. 스키마와 제약조건은 준비돼 있다 |
| SFOC·과급기 효율 (FR-401, 402) | 수집·진단 경로를 끝까지 잇는 것을 먼저 했다 | 필요한 계측값(연료유량, 축 출력)은 이미 적재 중이라 조회 API 만 추가하면 된다 |
| 마스터 등록·수정 (FR-201~203) | 선박 4척은 시드로 충분하다 | 인증과 함께 구현한다. 등록 권한이 ADMIN 이기 때문이다 |
| 디스크 큐 (FR-104) | 메모리 큐로 단절·복구 동작을 먼저 검증했다 | Edge 재기동 시에도 버퍼가 남도록 파일 기반 큐로 교체 |
| HTTPS (NFR-05) | 도메인이 필요하다 | 배포 후 Let's Encrypt 적용. MQTT 구간의 TLS 는 v1.1 에서 적용했다 |
| 인증서 폐기·갱신 | 발급까지만 자동화했다 | 폐기 목록(CRL) 적용, 만료 전 갱신 절차 (`09` 5.6) |
| 본선 발행 알람 (NFR-10) | 알람 판정을 육상에 두기로 했다 (`02` ADR-009) | 단절 중 알람 확정이 필요해지면 구현한다 |
