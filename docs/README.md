## 읽는 순서

**처음 보신다면** → `01 요구사항정의서` 1~2장 (배경과 범위) → `02 아키텍처` 2장 (논리 구조) → `05 화면설계서`

**기술 구조가 궁금하다면** → `02 아키텍처` 전체, 특히 **9장 주요 설계 결정 기록(ADR)**

**실무 연계 방식이 궁금하다면** → `03 인터페이스 정의서` (OPC UA 태그맵, MQTT 페이로드 규격)

**코드가 어떻게 짜였는지 궁금하다면** → `06 프로그램 설계서` (모듈 구성, 처리 절차, 알람 엔진 상태 전이, API 명세)

**무엇이 구현되고 무엇이 남았는지 궁금하다면** → `10 요구사항 추적표`

**검증 결과가 궁금하다면** → `08 테스트결과서` → `10 요구사항 추적표`

## 이 프로젝트가 다루는 문제

선박용 대형 엔진은 항해 중 육상 지원을 받을 수 없어, 고장이 곧 운항 중단으로 직결됩니다.
본 시스템은 기관 운전 데이터를 육상에서 연속 감시하여,
**계획 정비(Planned Maintenance)에서 상태기반 정비(CBM)로 전환**하는 것을 목표로 합니다.

핵심 진단 기능은 **실린더 배기온도 편차 감시**입니다.
개별 실린더의 온도가 정상 범위 안에 있더라도 실린더 간 편차가 벌어지면
연료분사밸브 불량이나 배기밸브 누설의 조기 징후이며,
단순 임계값 감시로는 잡아낼 수 없습니다. (→ `01 요구사항정의서` FR-302)

## 문서 작성 규칙

- 모든 문서는 **표지 정보 블록**(문서명·버전·작성일·작성자·선행문서)과 **변경 이력**을 포함한다.
- 요구사항은 `FR-nnn`(기능) / `NFR-nn`(비기능), 테스트는 `TC-nnn`, 설계결정은 `ADR-nnn` 으로 식별한다.
- 설계 결정은 **선택한 것과 버린 대안, 그 근거**를 함께 남긴다.
- 문서 간 참조는 파일명과 장 번호로 명시한다.
